# Agent Note: Windows Release 下载断点续传

Status: implemented

[English](2026-09-19-windows-release-download-resume.md) | 中文

## 问题

Windows 安装器每次都把 Release 资产下载到新的临时目录。连接中断后，已下载的
部分会被丢弃，再次运行安装器只能重新下载整个文件。内置运行时较大，在网络
不稳定时尤其耗时。

## 决策

`install.ps1` 将未完成的资产保存在安装器数据根目录的 `downloads` 目录，
文件名由 Release 资产名和发布的 SHA-256 确定。再次运行时从已有字节数发送
HTTP Range 请求。有效的 `206` 响应必须从该偏移开始，并声明预期的文件总大小。
如果镜像站返回 `200`，安装器会用完整响应覆盖部分文件。未完成的下载保留供
下次重试。

安装器仍在改动现有安装之前校验完整文件与 Release 摘要。摘要不匹配时删除
缓存文件；安装成功后也删除。下载请求始终不携带 GitHub API 令牌，包括使用
自定义镜像站时。

## 曾考虑的替代方案

**使用 PowerShell 的 `Invoke-WebRequest -Resume`。** 安装器支持的 PowerShell
5.1 没有这个参数。基于 .NET 的流式请求可同时支持 5.1 和更新版本的 Range 行为。

**把部分文件保留在随机临时工作目录。** 安装器退出时会删除该目录，无法用于
下次运行。现有安装器数据根目录提供稳定的缓存位置，无需另设状态根目录。

## 后果

下载中断后可以重新运行同一安装命令续传。不支持 Range 的服务器会触发完整
重下，但不会把完整响应错误地追加到部分文件。部分文件在成功重试或手动清理
前会占用磁盘空间。这只是 Issue #213 中 Windows 安装器的一部分，不包含其他
平台或界面的差分更新。

## 测试

Windows 安装器测试模拟连接中断后返回 `206` 续传，以及镜像站忽略 Range 的
情况。两条路径都只在发布摘要校验通过后安装；续传测试还确认安装成功后删除
缓存。
