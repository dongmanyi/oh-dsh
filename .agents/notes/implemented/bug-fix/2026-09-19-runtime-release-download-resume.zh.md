# Agent Note: 运行时 Release 下载断点续传

Status: implemented

[English](2026-09-19-runtime-release-download-resume.md) | 中文

## 问题

Desktop 运行时更新器每次尝试都会从头写入下载文件。连接失败后虽然磁盘上
留下了部分字节，再次点击 Update Runtime 仍无法利用。运行时包体积较大，
网络不稳定时需要反复完整下载。

## 决策

下载前先获取发布的 SHA-256 校验文件。若存在，以摘要作为部分文件缓存键，
重试时使用 HTTP Range 请求剩余字节。仅在服务器返回 HTTP 206，且
Content-Range 与缓存偏移和预期总长度一致时才追加。服务器忽略 Range
并返回 HTTP 200 时，用完整响应覆盖部分文件。错误的范围响应及摘要
不匹配的文件会被删除。只有校验通过的包才进入解压、冒烟检查和指针激活。

没有有效 SHA-256 校验文件的旧版 Release 继续完整下载。这保留了兼容性，
同时避免复用无法与发布摘要绑定的部分字节。成功激活后删除下载缓存；
传输中断时保留部分文件。

## 曾考虑的替代方案

**只按文件名续传已有归档。** 文件名不能唯一标识发布内容。若 Release
内容发生变化，可能把两个不同包的字节拼在一起；以摘要作为缓存键可以
避免这种混淆。

**强制服务器支持 Range。** 镜像站可能忽略 Range。用完整的 HTTP 200
响应覆盖部分文件，仍可完成更新。

## 后果

对发布了 SHA-256 校验文件的运行时包，网络中断后重试可以节省下载量。
部分文件在成功更新或手动清理前会占用磁盘。原有暂存、激活及回退规则
保持不变。这只是 Issue #213 的一部分；不引入 blockmap 差分更新，
也不改变 Desktop 应用更新。

## 测试

运行时更新测试模拟连接中断后返回有效 HTTP 206，以及服务器忽略 Range。
测试确认请求偏移、成功激活及部分文件清理。
