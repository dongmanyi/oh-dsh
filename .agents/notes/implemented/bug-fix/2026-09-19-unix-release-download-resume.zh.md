# Agent Note: macOS 与 Linux Release 下载断点续传

Status: implemented

[English](2026-09-19-unix-release-download-resume.md) | 中文

## 问题

`install.sh` 每次都把 Release 资产下载到新的临时目录。连接中断后，已下载的
部分会被丢弃，再次运行只能重新下载整个文件。发行包包含运行时，在不稳定的
网络上这一问题更明显。

## 决策

安装器把未完成的 Release 资产保存在现有安装记录根目录的 `downloads` 目录，
以资产名和发布的 SHA-256 作为缓存键。再次运行时，curl 根据已有字节数使用
HTTP Range 续传。若 curl 报告服务器不支持续传（退出码 33），安装器会删除
部分文件，从头重新下载。完整且已通过校验的缓存可直接复用，无需网络请求。
若记录根目录无法存放下载文件，本次运行改用临时暂存目录；提交安装记录时的
错误仍会正常报告。

安装器在改动现有安装之前校验发布的 SHA-256。摘要不匹配时删除缓存文件，
下载失败时保留缓存；安装成功后删除缓存。Release 下载始终不携带 GitHub
API 令牌，包括配置自定义镜像站时。

## 曾考虑的替代方案

**在多次运行间保留临时下载目录。** 现有临时目录名称每次随机产生，并在退出
时删除。复用它会混淆暂存文件和持久状态；现有安装记录根目录已提供稳定位置。

**假定所有服务器都支持 Range。** 自定义镜像站可能忽略该请求。安装器在
curl 报告续传失败后重新下载完整资产，最终仍由摘要校验保护。

## 后果

macOS 和 Linux 安装器在传输中断后，可以重新运行同一命令续传。部分文件
会在成功重试或手动清理前占用磁盘空间。这只是 Issue #213 的安装器部分，
不包含 blockmap 差分更新，也不修改运行时更新管理器。

## 测试

安装脚本测试模拟连接中断后使用 Range 续传，以及镜像站忽略 Range 的情况。
两条路径都在摘要校验前保持原安装不变；续传测试还确认安装成功后删除缓存。
